# Giver — памятка для новых сессий

Игра для телефона (Android): **спуск в Бездну** — огромную вертикальную шахту — с лазанием руками,
верёвкой и тросом. Жанр — как у кооперативных «лазалок» (механика — по мотивам PEAK, просил пользователь),
но **своя игра**: свой мир, герой, ярусы и правила — не копировать чужие игры и аниме (никаких названий,
персонажей, «проклятия», свистков и т. п. из Made in Abyss; ничего конкретного из PEAK). Пользователь пишет
по-русски, отвечать по-русски, просто, по шагам: он работает с телефона и присылает скриншоты.

## Ветки и сборки (с 0.5)

- `main` — РАБОЧАЯ версия (сейчас 0.4) → приложение «Giver» (`com.giver.game`), релиз `latest`, `Giver.apk`.
  **Без согласия пользователя в main не пушить.**
- `dev` — разработка 0.5 → отдельное приложение «Giver Тест» (`com.giver.game.test`, свой значок с меткой «Т»),
  ставится РЯДОМ с рабочим, сохранения отдельные. Релиз `test` (prerelease), файл `GiverTest.apk`:
  `https://github.com/zlontp98-bit/Giver/releases/download/test/GiverTest.apk`. Сборка — при push в `dev`
  (`.github/workflows/build-apk.yml`: ветка main → `latest`, любая другая → `test`, флаг gradle `-PgiverTest`).
- `archive-0.4` — полная 0.4 (4 яруса до дна) — пользователь просил не удалять ярусы 2–4 безвозвратно.
  Метки (tags) отсюда запушить нельзя (403 от политики доступа) — поэтому архив в ветке.

## Что сейчас в игре (версия 0.4 — Бездна; 0.1–0.3 были восхождением на гору)

- Плато с лесом и лагерем, посередине — Бездна глубиной 232 м. Четыре яруса со своими цветом, дымкой и
  светом: Устье (0), Корневой ярус (−55), Хрустальные гроты (−115), Дно (−178…−232). Чем глубже — темнее,
  гуще дымка, ярче фонарик на шапке героя, светятся кристаллы и жилки в скале.
- Механика (как в PEAK, но своя): **Хват** у стены — висишь на руках, джойстик — вверх/вниз/вбок,
  силы тают (6.5/с в движении, 2.2/с на месте), кончились — сорвался. Можно схватиться за стену в падении
  (−10 сил) и спуститься с края плато в любом месте. Падение > 6 м ранит, > 32 м — смерть.
- Связки между уступами (`descent.js`): мостки с края, спуск руками по голой стене (меловые метки),
  кольцо для верёвки (Крюк → джойстик вниз — травить верёвку), парящие камни (прыжки, один качается),
  трос через всю шахту (Крюк у кольца → едешь, в конце тормоз), огромный гриб (гасит падение).
- Лагеря (3, первая полка каждого яруса) — точки сохранения; ягоды — силы; осколки (49) — собирать.
  Цель — огромный кристалл на дне. Подсказка каждого вида — только в первый раз.

## Нагрев телефона — пользователь жаловался, что телефон сильно греется (0.3, сохранено в 0.4)

- По умолчанию «Низкая» (ключ сохранения `quality2`, старый `quality` из 0.2 игнорируется).
- Не больше 30 кадров/с на низкой и средней, 60 на высокой, 15 в меню/паузе (`frame()` в main.js) —
  без этого телефоны с экраном 90–120 Гц рисуют в 2–4 раза больше кадров.
- Эффекты postprocessing (свечение, AO, SMAA) — только на «Высокой». Тени: «Средняя» и «Высокая»,
  пересчёт не каждый кадр (`shadowMap.autoUpdate = false`, когда «солнце» сдвинулось и раз в 4 кадра);
  герой тень не отбрасывает — под ним свой кружок.
- Скалы: 3 варианта шейдера (`terrainMaterial(0|1|2)`: без текстур / текстуры цвета / + неровности).
  Крупные пятна и слои породы считаются в вершинах (`vRock`), в каждой точке — один шум; жилки — только
  глубже 100 м. Стена Бездны порезана на 60 кусков (`wallMeshes`) — невидимые не рисуются, в тенях тоже.
- Света: у костров нет своих ламп — один общий `localLight` переезжает к ближайшему костру/кристаллу на дне;
  ещё `fillLight` (подсветка стен изнутри шахты) и фонарик героя. Новые лампы не добавлять без нужды.
- Трава, камни и трава на стенах — `gfx.grass` (на «Низкой» рисуется 25% экземпляров, начало списка).
- Замер (SwiftShader, экран 915×412 ×2.6, на стене на глубине 40 м, после прогрева): «Низкая» ~70–100 мс/кадр
  (в 0.3 на горе было 148), «Средняя» ~290–340 (было 368). Скрипт — `tools/perf.cjs`.

- Сборка: `npm ci && npm run build`. Всё (модели, текстуры, шрифты) внутри game.js — работает офлайн.
- Страница в APK: `file:///android_asset/web/index.html` — не менять (сохранение привязано к адресу).
  Скрипт обычный (не модуль). Мост: `window.AndroidBridge.exit()`, `window.__onBack()`.
- Сохранение: localStorage `giver_v1` (имя не менять), формат 2: `{ v: 2, settings: { quality, showFps },
  records: { abyss: { time, shards }, mountain: { time, stars } }, progress: null (заполнится в этапах 0.5),
  bench: [последние 8 «Замеров»] }`. Плоские записи 0.2–0.4 (`quality2`, `best2`, `bestShards2`, `best`,
  `bestStars`) переводятся автоматически (`migrate()` в core/save.js).
- Эффекты (postprocessing): на экран рисует ПОСЛЕДНИЙ добавленный слой — лишние слои убирать
  (`configureComposer`), а не выключать `enabled=false`, иначе чёрный/пустой экран.
- Instanced-цвет в фрагментном шейдере three.js виден как `USE_COLOR` (не `USE_INSTANCING_COLOR`).

## Как устроена Бездна (abyss.js, descent.js)

- Угол θ: `x = sin θ · r, z = cos θ · r`, ось шахты — x = z = 0. Стена — `wallR(θ, y)` (≈41–56 м).
- Полка: `{ y, th1, span, depth, thick }` — кусок кольца у стены; ширина сужается к концам (`ledgeDepth`).
- `plan()`: первая полка на −10 м (мостки с края), дальше по `PATTERN` до глубины ~−200, последняя
  связка — верёвка до дна. Для верёвки и гриба глубина нижней полки считается (`depthFor`), чтобы место
  приземления было на ней; для спуска руками нижняя полка начинается под концом верхней.
- Герой на стене: `climb = { th, y }`, позиция — в 0.42 м от стены; полки снизу/сбоку упираются,
  сбоку у верха полки — перелезает на неё, внизу — встаёт.
- `descent.route` — шаги для бота: walk / climb / rappel / zip / jumps / drop.

## Сборка APK

- APK собирает GitHub Actions при push в `main` (кроме правок только `*.md` и `experiments/**`) и
  вручную (`actions_run_trigger` → `run_workflow`, `build-apk.yml`). Кладёт `Giver.apk` в релиз `latest`.
- Скачать `https://github.com/zlontp98-bit/Giver/releases/download/latest/Giver.apk` через curl, сверить
  sha256 с digest релиза и отправить файлом (SendUserFile).
- Перед сборкой поднимать `versionCode`/`versionName` в `android/app/build.gradle` (в main 4 / 0.4,
  в dev 5 / 0.5-a0; тестовые сборки дальше 0.5-a1, a2…).
  Подпись — `android/app/debug.keystore` (пароль android), ставится поверх.

## Как проверять

- Chromium через Playwright, `args: ['--enable-unsafe-swiftshader', '--use-angle=swiftshader']`.
  Скриншоты — с `deviceScaleFactor: 1` или 2 и `timeout` побольше; `window.__noAdapt = true` — чтобы
  игра не понижала качество (в SwiftShader всё «тормозит»).
- Готовые проверки (после `npm run build`): `node tools/bot.cjs` — бот проходит всю Бездну (0.5-a0: 134/134 шагов,
  49/49 осколков, без урона, 231 с игрового времени до кристалла), `node tools/flows.cjs` — падение/экраны/«Хват»
  пальцем/пауза, `node tools/bench.cjs` — перевод старого сохранения, счётчик FPS, «Замер» и его прерывание
  «Назад», настройки после перезапуска, `node tools/perf.cjs low` — сколько стоит кадр и его части.
- «Замер» на телефоне: пауза → «Замер скорости · 30 с» → итог (средний FPS без ограничения, загрузка в игре
  = лимит/FPS, 1% медленных кадров, работа процессора, видеочип). Пользователь присылает скриншот — это
  единственные настоящие цифры с телефона; история последних замеров видна там же.
- `window.__giver` = `{ game, player, abyss, descent, world, cam, input, gfx, setQuality, step(inp) }`.
  `step()` — один шаг физики без рисования (`game.running = false`, чтобы кадры не двигали героя).
  Бот идёт по `descent.route`: walk — поворачивать `cam.yaw` на цель и `my = 1`; climb — `grab`, вбок
  (`mx`, камера смотрит на стену) до `theta`, потом вниз; rappel/zip — `player.pickTarget(dir)` + `hook`,
  на верёвке `my = -1`; jumps/drop — разбег, прыжок у края, в воздухе рулить к центру цели.
  Последний прогон (0.4): дно за ~4.4 мин игрового времени, 49/49 осколков, без урона.
  Проверено ещё: падение в бездну → экран → «Продолжить»; «Хват» пальцем у края, отпустить и поймать
  стену в падении; пауза кнопкой «Назад».
- Касания — pointer-события (`pointerType: 'touch'`) на `#layer` и кнопках `#bGrab`, `#bHook`, `#bJump`, `#bRun`.
